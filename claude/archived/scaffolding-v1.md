# Scaffolding -- v1

*Archived 2026-10-09: superseded, Mentes moved to its own repository
(tag `mentes-final`).*

Plan for the initial Gradle project: an empty Compose desktop window that
builds and runs, with the toolchain pinned so that nothing depends on the
JDK installed on the machine.

## Decisions

| Component | Version | Notes |
|---|---|---|
| Gradle | 9.8.0 | Pinned by the wrapper. |
| Kotlin | 2.4.20 | Gradle plugin, nothing to install. |
| Compose Multiplatform | 1.12.x (latest patch at implementation time) | Gradle plugin. |
| JDK | 25 (LTS) | Provisioned by Gradle, never by apt. |
| Targets | Desktop (JVM) only, for now | |

### JDK independence

The system JDK (whatever `java` is on `PATH`, or `JAVA_HOME`) must not
matter. Three mechanisms:

1. **Daemon JVM criteria** (`gradle/gradle-daemon-jvm.properties`,
   generated by `updateDaemonJvm`): the Gradle daemon always runs on JDK 25.
2. **Foojay toolchain resolver** (`org.gradle.toolchains.foojay-resolver-convention`
   in `settings.gradle.kts`): if JDK 25 is not found locally, Gradle
   downloads it into `~/.gradle/jdks`.
3. **`jvmToolchain(25)`** in the build: Kotlin compiles against JDK 25.

Because the daemon runs on 25, Compose's `jpackage`-based packaging also
uses 25 and bundles it, with no `javaHome` override.

Residual dependency: the `./gradlew` launcher itself starts on the system
`java` and Gradle 9 requires it to be at least 17. It is only a thin client;
anything from 17 upward works. Older fails fast with a clear error.

### Kotlin Multiplatform plugin with a single JVM target

Desktop only, but use `org.jetbrains.kotlin.multiplatform` with one `jvm()`
target rather than `org.jetbrains.kotlin.jvm`. chip-wishlist-v4.md
anticipates Android and Web later; with the multiplatform plugin, adding them
means adding targets and source sets, not migrating the build.

### Version catalog

All versions and plugin ids live in `gradle/libs.versions.toml`. Build
scripts reference `libs.*` only, no inline version numbers.

## Layout

```
settings.gradle.kts            foojay plugin, repositories, include(":composeApp")
build.gradle.kts               plugins declared with `apply false`
gradle.properties              Gradle/Kotlin flags (configuration cache, etc.)
gradle/libs.versions.toml
gradle/gradle-daemon-jvm.properties   generated
gradle/wrapper/...             generated
gradlew, gradlew.bat           generated
composeApp/build.gradle.kts    kotlin { jvm(); jvmToolchain(25) }, compose.desktop { application { ... } }
composeApp/src/jvmMain/kotlin/io/github/cigizeta/mentes/Main.kt   empty window titled "Mentes"
```

## Steps

1. Claude writes `settings.gradle.kts` (Gradle 9 refuses to run without one).
2. Developer generates the wrapper with the system Gradle (9.4.1 is fine):
   `gradle wrapper --gradle-version 9.8.0`.
3. Developer generates the daemon JVM criteria:
   `./gradlew updateDaemonJvm --jvm-version=25`.
4. Claude writes the version catalog, root and module build scripts,
   `gradle.properties`, and `Main.kt`, and adds `include(":composeApp")` to
   `settings.gradle.kts` (deferred until now because Gradle 9 rejects an
   included project whose directory does not exist).
5. Developer runs `./gradlew :composeApp:run` and sees the window.
6. Claude updates the Gradle section of CLAUDE.md with the real task names
   (run, test, package).
7. Developer commits, including the wrapper jar and the daemon JVM properties.

## Naming

- **Base package**: `io.github.cigizeta.mentes`.
- **Module**: `composeApp` (the JetBrains wizard default).
- **Foojay plugin**: 1.0.0 (latest on plugins.gradle.org at planning time).
